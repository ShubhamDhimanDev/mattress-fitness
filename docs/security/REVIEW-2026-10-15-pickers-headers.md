# Security review: cart pickers (gift, add-on, bundle), response headers, SEO routes, log redaction (commits 07d8e57, 594fc27, e5a236a)

Reviewer: security-engineer. Date: 2026-10-15. Branch `feat/p4-pickers-p7-seo-headers`. Previous review: [REVIEW-2026-10-14-extend-ui](REVIEW-2026-10-14-extend-ui.md).

Scope: `offers-runtime/{picker-steps,cart-gate}.ts`, `cart/{actions,custom-actions}.ts`, `routes/{cart,checkout-steps,cart.$lines}.tsx`, `components/cart/CartOffers`, `offers/{gifts,bundles,addons,gift-price}.ts`, `lib/security-headers.ts`, `entry.server.tsx`, `server.ts` (the uncommitted diff, committed meanwhile as e5a236a), `lib/seo/**`, `[robots.txt]`, sitemap routes, `lib/logging/**`, the allow-listed direct `console` calls. Threats: T-01, T-02, T-05, T-07, T-08, T-10, T-13.

This review covers the committed state up to e5a236a as read at the start; the later uncommitted edits are NOT reviewed and need a re-check.

Method: code reading with hostile cases; 22 Vitest files (841 tests: picker steps and routes, offers, security headers, logging, seo, no-direct-console) pass; esbuild-bundled probe scripts in the scratchpad (redaction with 58 inputs and 16 large-input timings, HSTS/CSP/canonical/sitemap helpers with spoofed hosts, `toCents`); dev server on port 4700 (mock.shop, throwaway carts, no `.env` read) and a production build served with `hydrogen preview` on 4700 using a scratch env file outside the repo (throwaway secrets, `PUBLIC_SITE_URL=https://shop.example.test`); curl with forged Host, `X-Forwarded-Proto`, Origin and hostile cart payloads; `npm audit --omit=dev`; `dist/client` grep (98 assets); added-line secret scan of `98eeec0~3..HEAD`. Both servers were killed; port 4700 verified free. No source changed.

## Gate verdict

**PASS WITH CONDITIONS (proposed).** No High. Browser input on the three new actions is limited to a rule, bundle, variant or line id; the server re-judges the cart it reads back from Shopify and derives variant, quantity and lines; the gate runs again after every request and at hand-off. Headers and canonical/sitemap/robots do not trust Host (P-L2 holds in a production build). Conditions: K-M1 (gift-not-free needs a development-store run, V-03) before any store takes orders; K-L1 to K-L3 before launch; H-1 (ADR-0008) and the ADR-0006/O-M3 owner acceptance unchanged.

## Findings

### High
None.

### Medium

**K-M1. Gift-not-free gate fails closed and has never seen a real Shopify cart (T-02; V-03).**
Evidence: `cart-gate.ts:31-48` (`lineTotalsOf` reads `cost.totalAmount`), `gift-price.ts` (`total === undefined || total !== 0` means not free), `cart-gate.ts:155-165`. `toCents` throws on `-0.00`, `0.001`, `1e-9`, empty: unreadable means "not free" (probed), which is the safe direction. Scenario: if the store's gift discount does not zero `totalAmount` as assumed, is deactivated, or does not combine with a code the shopper typed, every cart with a gift is paused at `/checkout-steps` ("Remove the gift to continue"). It cannot be used against another shopper (carts are per cookie) and cannot lower a price. Impact: availability and revenue if the assumption is wrong; no leak. Fix: run on a development store with a real automatic gift discount (V-03) and confirm `totalAmount` after discount, code combination and a 2-unit gift; tell staff gift variants must be dedicated variants (a gift variant also sold normally is classified gift by `classifyLine`). Due: before any store takes orders.

### Low

**K-L1. Redaction layer: gaps in the safety net (T-05).** Evidence (probe output):
- `redact.ts:225-245` unquoted multi-word value: `name=Jane Doe&city=Austin` becomes `name=[redacted] Doe&city=Austin` (the tail after the space leaks; `VALUE_STOP` includes whitespace). Same for cookie/header-like text.
- `redact.ts:339`: Shopify attribute pairs `{key:'delivery_zip', value:'90210'}` redact the word `key` and keep the `value` (also `zipcode`, gift messages). No call site logs such objects today (every `logError/logWarn` call passes codes, counts or `errorName`), so this is latent.
- Key names not matched: `pc`, `zp`, `ship_to`, `recipient`, `contactName`, `cell`, `msisdn`, `birthday`, `dateOfBirth`, `orderNote`, `ip`; content not matched: bare ZIP in prose (`No delivery to 90210`, `Austin, TX 78701`), order ids and order gids (customer and cart gids are redacted; order ids are logged on purpose by the detective check), IPs, PO boxes.
- Strengths: errors become `Error(<name>)`, Map/Set/Headers/Buffer become `[object]`, depth/keys/items/length caps, `__proto__` stays data, cart `?key=`, checkout paths, emails (including `%40` and Unicode), phones with separators, JSON text keys are covered. Large inputs (1 MB of repeated `a.`, `x=`, quotes, `%40`, 100k-key object, 100k-deep array) ran in 0.1 to 22 ms: no regex DoS (input is cut to 4,000 characters first).
Fix: stop the value at the next `&`, `;`, `,` or end for unquoted values with a sensitive key (or redact to end of line, capped); treat `{key, value}` pairs by the key's name; add the key names above; keep the rule "callers pass ids and codes". Re-rated: Low while no caller logs free text; Medium the day one does.

**K-L2. Allow-listed direct `console` calls log `error.message` unredacted (T-05).** Evidence: `routes/cart.tsx:221,263`, `routes/checkout-steps.tsx:83`, `offers-runtime/facts.ts:19`; `server.ts` also logs a path (query string stripped) and an error name only (N-L4 closed: `appendSetCookie`, `describeError`). Hydrogen's `GraphQLError.message` is Shopify's text plus `Request ID` (query and variables sit in `cause`, not logged), so no PII is expected, but Shopify's wording for a bad cart or variant id may echo an id with its key. Remaining `console.error('Offer config:' ...)`, `'Offer facts incomplete:'`, `'Extend coverage inputs unavailable:'` (`server.ts:218,254,268`) log fixed codes. `no-direct-console.test.ts` only matches `console.x(` calls, not `.catch(console.error)` or aliases, and scans `app/` only (not `server.ts`). Fix: move these five to `logError(event, errorFields(error))` and drop them from the allow-list.

**K-L3. Offer-only products can appear in the sitemap and have indexable product pages (T-06 hygiene; T-02 unaffected).** `getSitemap` lists whatever Shopify's `sitemap(type: PRODUCT)` returns; Extend price-point products, the haul-away service, gift variants and comfort protectors must be published to the headless channel to be added to a cart, so they are probably listed, and nothing in `products.$handle.tsx` or the admin guide hides them. Buying coverage or haul-away alone is still refused by the gate, so this is crawl exposure and shopper confusion. Fix: set Shopify's `seo.hidden` metafield on those products (verify on the development store that the Storefront sitemap honours it, V-05) and add it to the admin guide; optionally emit `noindex` on those PDPs.

**K-L4. Bundle saving figure is not a bundle saving (T-01 honesty, display only).** `cart-gate.ts:66-80,125-139`: sums every `LINE_ITEM` allocation on the anchor line and on every line holding a companion variant, so a typed code or an unrelated automatic discount counts, and a companion shared by two anchors or two bundles is summed twice. The wording is "savings on these items" and no price or entitlement depends on it (Shopify prices; nothing is added because of it). Confirmed as Low (consumer-claim accuracy). Fix: attribute allocations to the bundle by discount title (the field is already fetched) and count each line once.

**K-L5. Concurrent picker posts can duplicate lines (T-02, integrity).** `picker-steps.ts:165-228`: two parallel `CustomAddBundle` or `CustomAddAddOn` requests both judge the same cart and both add; `before`/`after` at `:202-203` is a read-modify-read. Gifts are safe because the gate then removes the extra (`duplicate-gift`, `gift-over-limit`, tested). Bundles and add-ons are ordinary paid lines, so the cost falls on the shopper, with no discount gained (Shopify decides the saving). Confirmed Low. Fix: accept as is, or add an idempotency token per form render.

**K-L6. Response headers miss two paths (T-07/T-10, hygiene).** `server.ts:43` (`storefrontRedirect`, a redirect it builds) and `server.ts:58` (the 500 text response) return without the security headers because they are created after `applySecurityHeaders`. Content is a redirect or fixed text, so the effect is small; no `nosniff` on a text/plain 500. Fix: apply `withSecurityHeaders` to the final response in one place (an in-flight edit adds that helper). Also `powered-by: Shopify, Hydrogen` is still sent (known gap in SECURITY_HEADERS.md).

**K-L7. e2e console filter can hide CSP violations (T-10 evidence).** `tests/e2e/helpers/a11y.ts:43-45` and `shell.spec.ts:46` drop any console message containing `shopifysvc.com`. A violation naming another host that merely contains that string (for example `monorail-edge.shopifysvc.com.attacker.example`) or a different directive would be ignored, so the "no violation" claim in SECURITY_HEADERS.md is weaker than stated. Fix: match the exact blocked URI `https://monorail-edge.shopifysvc.com` and the directive, and fail on everything else.

**K-L8. Picker actions double the upstream cost per POST (T-13, extends N-M1).** `judge()` runs a full gate (cart, product facts, Extend inputs, offered variants, bundle variants) and the route runs it again after the mutation. With no rate limit until Q-003, an unauthenticated client can generate several Storefront and Extend calls per request, and the permalink and `/discount/:code` still create a cart per GET. Fix: host rate limit (Q-003); pass the first gate's cart to the second where nothing changed.

**K-L9. Sitemap routes (T-13, SEO).** Out-of-range pages (`/sitemap/products/99.xml`) return 200 with a single home-page `<url>` (Hydrogen's empty-page output through the `getLink` fallback) and a one-day public cache; any query string (`?x=1`) varies the cache key and reaches the origin. Fix: return 404 when the page has no items; ignore the query string in the cache key at the CDN.

### Info
- robots.txt (`seo/robots.ts`) names `/api`, `/webhooks`, `/checkout-steps`, `/delivery`, `/discount` as prefixes. These are already visible from page links and are protected by HMAC, origin checks and the gate, so it reveals nothing usable; nothing admin-like is listed (`/_dev` is not in robots and returns 404 in a production build, verified). `/policies` is disallowed, which hides legal pages from search: an SEO decision for the owner, not a security issue.
- HSTS (`security-headers.ts:55-101`): the host rule rejects localhost, `*.localhost`, IPv4 (dotted and `127.1`, `2130706433` forms, normalised by the URL parser), IPv6 and single labels; `https://localhost./` (trailing dot) and `.local`/`.internal` names count as public. A spoofed `X-Forwarded-Proto: https` with a public Host gets HSTS on its own response only (browsers ignore HSTS over http); only the first forwarded value counts (`http, https` gives none). Verified in the production preview.
- COOP `same-origin-allow-popups`, `X-Frame-Options: DENY`, `Permissions-Policy: payment=()...`: no flow on our domain needs them off. Checkout and the customer account are top-level navigations to Shopify's origins (302 from `/checkout-steps`, `/account/login`, `/account/logout`); the only `target=_blank` links carry `noopener`/`noreferrer`; no Shop Pay button, Payment Request, geolocation or `window.open` exists in `app/`. The report-only `form-action` lists `shopify.com` and the store/checkout domains: if the customer account lives on a custom `account.<domain>`, it will report a violation (cannot verify without a real store).

## Verified

**Picker actions (T-01, T-02, T-08), code, tests and live.**
- Forged rule id, variant id, bundle id, anchor line id: `validateAddGift/AddAddOn/AddBundle` (`actions.ts` offer-id: 1 to 120 characters, no control characters; variant and line id regexes) then meaning is proven against the engine: `view.gifts` must contain the rule, the rule's own size map must contain the variant, and the view must show it in stock (`picker-steps.ts:109-119`); add-ons must be in `view.addOns` for a mattress in THIS cart (size match, `:138-141`); bundles must be `incomplete` in the view AND re-derived by `bundleCompletions`, with the anchor id found in the server's own cart (`:175-191`). A foreign cart's line id never matches, so it is refused. Quantity is always server-chosen (1, or the derived missing quantity); a `quantity` or `price` field in the request is dropped (tested). Live: cross-origin Origin gave 400 (React Router's own origin check answers before our 403; the route test proves our 403), forged payloads with markup, control characters, `__proto__`, bad ids and an unknown action got 400 with fixed text and no echo; a body of 200 KB got 413; every response `private, no-store`.
- Gift without qualifier or over the allowance: refused in `addGift`; added by other routes (generic `LinesAdd`, permalink, stepper through `LinesUpdate`) it is removed or clamped by `evaluateGifts` (`orphan-gift`, `duplicate-gift`, `gift-over-limit`) on the next gate, which runs after every cart request and at hand-off. `/cart/:lines` permalink with a gift variant goes through `/checkout-steps`, so the same gate applies. The gift-not-free pause cannot be aimed at another shopper and keeps `skip=1` from passing a blocked cart (`checkout-steps.tsx:127`).
- CSRF/error text: all picker failures use fixed texts (`PICKER_STEP_FAILURE_TEXT`); Shopify `userErrors` pass through as before. The cart cookie is `HttpOnly; SameSite=Lax` (live), and `isSameOriginRequest` is unchanged.
- Bundle partial-add: the discount is Shopify's, never ours; partial state is reported from the cart read back (`:202-215`), and a complete bundle shows a saving only when Shopify reports one.

**Headers (T-07, T-10).** Production preview: `/` carries Hydrogen's enforced CSP and the report-only policy with `https://mock.shop` for the store and no localhost source (dev adds localhost only); no `report-uri`, so nothing leaves the browser; resource routes (`/api/extend/offers`, `/webhooks/shopify`, cart JSON, redirects, 404) now carry the headers (dev and production); a malicious `PUBLIC_STORE_DOMAIN`/`CHECKOUT_DOMAIN` or nonce (newline, `;`, space, path, port, wildcard, underscore, trailing dot) adds no directive (13 hostile hosts, 4 nonces).

**Canonical, Link, sitemap, robots (P-L2).** With `PUBLIC_SITE_URL` set, `Host: evil.example` produced canonical `Link`, robots `Sitemap:` and sitemap `<loc>` values on the configured origin only; the canonical helper refuses `//host`, case and percent-encoded `/CART`, `/%63art`, `/Account`, and non-indexable prefixes; angle brackets and quotes in the path are percent-encoded so the `Link` value cannot be broken; XML escaping and handle validation hold. `extras.xml` lists only real brands/stores (mock store: `/` and `/collections`).

**Secrets and dependencies (T-04, T-12).** No credential-shaped value in `98eeec0~3..HEAD` except synthetic redaction fixtures (`sk_live_...`, `ghp_...`, a sample JWT); only `.env.example` is tracked; 0 hits in 98 `dist/client` assets for the private variable names, `loadCoverageCatalog`, `revalidateCartGate`, `addGift`, `readDeliveryZip`. No `package.json` or lockfile change in these commits. `npm audit --omit=dev`: 7 findings (2 high), same set as ADR-0008 (react-router, lodash, esbuild dev server on Windows): H-1 unchanged.
