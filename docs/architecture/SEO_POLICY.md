# SEO policy: canonical URLs, faceted URLs, robots and sitemap

Requirement REQ-SEO-001; task P7-04; decision DEC-044. Code: `storefront/app/lib/seo/` (pure, unit-tested), the routes `[robots.txt]`, `[sitemap.xml]`, `sitemap.$type.$page[.xml]`, `sitemap.extras[.xml]`, `entry.server.tsx` (Link header) and `collections.$handle.tsx` (tag). Status 2026-10-15: **built and verified on the dev server against a mock store; not verified on the real store or host.**

## Origin

Every absolute URL (canonical, sitemap, robots `Sitemap:` line, JSON-LD) uses `PUBLIC_SITE_URL` through `app/lib/site-origin.ts`. Development falls back to the request's own origin; elsewhere a missing value means **no canonical, no breadcrumb markup, a 404 for the sitemaps and no `Sitemap:` line**, never the Host header (P-L2). Set it before launch ([DEPLOYMENT](../deployment/DEPLOYMENT.md)).

## Canonical URL

One rule: **origin + path, no query string, no fragment, no trailing slash (except `/`)**. So these all share one canonical: `/collections/firm`, `/collections/firm?size=queen`, `/collections/firm?sort=price-asc&cursor=...`, `/products/x?Size=Queen` and any tracking parameters. It is sent two ways from the same helper (`canonicalUrl`):

- an HTTP `Link: <url>; rel="canonical"` header on every indexable `200` GET document (`entry.server.tsx`), which covers all templates at once;
- a `<link rel="canonical">` tag from the `meta` function of `collections.$handle.tsx`. Other templates (product, brand, page, store, blog) rely on the header until their owners add the tag with `canonicalMeta()`.

Never canonical (and never in the sitemap): `/cart`, `/account`, `/checkout-steps`, `/delivery`, `/api`, `/webhooks`, `/discount`, `/search`, `/compare`, `/policies`, `/sitemap*`, `/robots.txt`, `/_dev`. Matching ignores case and percent-encoding because routes do.

## Faceted URLs (decision)

Filters, sort and the load-more cursor live in the query string (`size`, `brand`, `product_type`, `comfort`, `mattress_type`, `benefit`, `position`, `product_line`, `price_min`, `price_max`, `sort`, `cursor`: `MANAGED_FILTER_PARAMS`). Policy:

1. The plain collection and brand pages are indexed and listed in the sitemap.
2. Any filtered, sorted or paginated view **canonicalises to the plain URL**. It is not `noindex`: a `noindex` combined with a canonical to another URL is a mixed signal, and a `noindex` cannot be seen on a URL that robots.txt blocks.
3. robots.txt also **blocks crawling** of every managed parameter (`Disallow: /*?*size=` and so on, generated from the codec so a new filter is covered automatically), to save crawl budget on combinations that all point at the same page. Accepted trade-off: a blocked URL that other sites link to can appear in results without a snippet; the canonical cannot be read there. Nothing on our own pages links to a filtered URL as a crawlable `<a href>` target that matters for ranking, and the 400-product catalog is small.
4. Internal search results are `noindex,follow` and blocked in robots.txt; there is no canonical.
5. Curated landing pages that should rank for a facet ("firm mattresses") are **collections** (Shopify collection or brand page), not filter URLs.
6. Revisit if the client wants a specific single-filter page indexed: it becomes a collection.

## robots.txt

Generated by `buildRobotsTxt`. Blocks for every crawler group: `/cart`, `/account`, `/checkout-steps`, `/delivery`, `/api`, `/webhooks`, `/discount`, `/search`, `/policies`, `/quiz?` (quiz answers and results are query state; the bare `/quiz` stays open), and the facet parameters above. Shopify-default groups kept: `adsbot-google` (ignores `*`), `Nutch` (blocked entirely), `AhrefsBot`, `AhrefsSiteAudit`, `MJ12bot` (crawl delay 10) and `Pinterest` (1); each repeats the rules because a named group ignores `*`. Ends with `Sitemap: <origin>/sitemap.xml`.

## Sitemap

`/sitemap.xml` is an index of Shopify's resource sitemaps (Hydrogen's `getSitemap`, up to 250 URLs per page, `lastmod` from Shopify) for **products, collections, pages, blogs and articles**, plus `/sitemap/extras.xml`:

- Metaobject sitemaps are **not** listed (no page exists for them) and there are **no locale alternates** (US English only, NFR-008; the template's `EN-CA`/`FR-CA` were removed).
- `extras.xml` lists `/` and `/collections`; `/brands` and every `/brands/<handle>` only from real `brand` metaobjects (the sample brands and a failed read list nothing); `/stores`, state, city and store pages only when the store list comes from Shopify. Today stores are fixtures (DEC-023, noindex), so none are listed. The quiz and compare pages are not listed.
- Handles are validated and percent-encoded; an unusable handle becomes the home page URL rather than a broken one. Unknown sitemap types and page numbers outside 1 to 100 are 404 before Shopify is called.
- Cached for a day (`public, max-age=86400`).
- **Assumption (unverified):** article handles from Shopify's sitemap arrive as `blog-handle/article-handle` and are linked as `/blogs/blog-handle/article-handle`. The mock store has no articles; check on the development store (V-05).

## Structured data

Product (with Offer or AggregateOffer), BreadcrumbList, FAQPage, LocalBusiness and Brand are built from the same data the page shows. `tests/unit/seo/structured-data.test.ts` checks each against the schema.org and Google rich-result required fields on recorded and fixture data, that **no rating or review markup exists anywhere** (no review source yet, Q-011), that an empty brand is omitted, and that hostile text cannot end the script block. There is **no Organization builder**; adding one needs the client's legal name, logo and profile links (not in the data model yet). Breadcrumb items must be absolute, so collections emit none without a site origin; the product, brand and store routes should do the same (not changed here, owned elsewhere).

## Titles and descriptions

Each route sets its own title through `formatPageTitle`. Unique `description` meta exists on collections, products, brands (real data only) and the quiz; a page-by-page audit of titles and descriptions on real content waits for the development store (P3A-01) and belongs to the Phase 7 gate.
